# 接口设计与契约（tech）

> 设计出「第一次用就猜对」的接口：资源命名、方法语义、错误模型、版本策略一次定清。

## 用途

- 设计新接口（HTTP / RPC / 库函数 / CLI）时定稿。
- 评审已有接口的缺陷与兼容性风险。
- 写出接口契约文档与示例。

## 何时使用

- 新增对外接口前；
- 接口被多方调用、投诉难用时；
- 需要写接口文档或 SDK 时；
- 评估接口变更的破坏性时。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 使用场景 | 谁在什么场景下调用、需要什么 | 必须有 |
| 现有接口风格 | 项目内已有接口的命名与错误约定 | 从代码抽取 |
| 数据模型 | 核心实体与字段 | 与用户确认 |
| 兼容性约束 | 是否有已发布版本 | 向用户确认 |

## 执行步骤

1. **写场景**：用「作为 <角色>，我需要 <动作>，以便 <结果>」写 3–5 条。
2. **建资源模型**：名词化资源，标出层级关系（不要照搬数据库表）。
3. **选方法语义**：标准方法（获取 / 列举 / 创建 / 更新 / 删除）+ 必要时自定义方法。
4. **定字段**：必填 / 可选；命名统一（`snake_case` 或 `camelCase` 择一）；时间用 RFC 3339。
5. **定错误模型**：统一的错误结构与错误码表；区分「客户端错」与「服务端错」。
6. **定幂等与重试**：哪些操作幂等、幂等键怎么传、超时后能否重试。
7. **定版本策略**：路径版本 / 字段版本 / 不兼容变更流程。
8. **写示例**：请求 + 响应 + 错误响应各一份（真实数据，不要占位符）。
9. **列兼容红线**：哪些是承诺不能变的。

## 设计要点

| 要点 | 做法 | 反例 |
|------|------|------|
| 资源命名 | 名词复数、URI 用复数名词 | `/getUserList` |
| 方法语义 | GET 安全、PUT 幂等、POST 非幂等 | 用 POST 做删除 |
| 层级 | 资源最多两层嵌套 | `/a/b/c/d/e` |
| 分页 | 统一游标或偏移，并说明排序稳定性 | 每页不同参数名 |
| 字段 | 同一概念同名同义 | `userName` / `username` / `login` |
| 错误 | 统一错误结构 + 机器可读错误码 | 只返回一段字符串 |
| 幂等 | 写操作支持幂等键 | 重试即重复下单 |
| 版本 | 不兼容变更走显式版本 | 静默改字段语义 |
| 时间 | RFC 3339 带时区 | 本地时间字符串 |
| 金额 | 整数最小单位 + 币种 | 浮点数 |

## 错误模型模板

```json
{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "human readable, safe to show",
    "status": 404,
    "details": [{ "field": "id", "reason": "not found" }],
    "request_id": "01J..."
  }
}
```

- `code` 稳定且可被程序判断；`message` 面向人且可本地化；
- 服务端内部错误不泄露堆栈、路径或 SQL；
- 校验错误用 `details` 指明字段。

## 破坏性变更判定

| 变更 | 是否破坏性 |
|------|-----------|
| 新增可选字段 | 否 |
| 新增接口 / 枚举值（客户端需容忍未知值） | 否（但要说明） |
| 删除字段 / 重命名字段 | 是 |
| 收紧校验（原本合法的输入被拒） | 是 |
| 放宽校验 | 否 |
| 改变字段语义（单位、时区、含义） | 是 |
| 改变错误码但保留原码为别名 | 否 |
| 改变默认排序或分页大小 | 视情况（可能影响既有客户端） |

## 输出格式

```markdown
## 使用场景
- 作为 <角色>，我需要 <动作>，以便 <结果>

## 资源模型
| 资源 | 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| Article | id | string | 是 | <...> |

## 接口
### GET /articles/{id}
- 用途：<...>
- 请求：<参数表>
- 响应 200：<示例>
- 响应 404：<示例>

## 错误码表
| code | HTTP | 含义 | 客户端应做什么 |
|------|------|------|--------------|

## 幂等与重试
| 操作 | 幂等 | 幂等键 | 超时后重试 |
|------|------|--------|-----------|

## 版本策略
<...>

## 兼容红线
- <不可变更的部分及原因>
```

## 质量检查清单

- [ ] 每个接口都能对应到至少一条使用场景；
- [ ] 资源是名词，方法语义标准；
- [ ] 字段命名、类型、格式全接口一致；
- [ ] 错误码表完整，且客户端有可执行的处理指引；
- [ ] 写操作的幂等性已说明；
- [ ] 版本策略写清楚了不兼容变更的流程；
- [ ] 示例是真实可用数据，不是 `foo` / `bar`；
- [ ] 兼容红线已列出。
