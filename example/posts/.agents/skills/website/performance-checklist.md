# 性能与体验体检（website）

> 用可测量的指标找出页面慢在哪，并给出按收益排序的优化清单。

## 用途

- 体检首屏加载、交互响应与视觉稳定性。
- 找出真正拖慢页面的少数资源（而不是全面微优化）。
- 建立发布前与发布后的性能基线。

## 何时使用

- 新主题 / 新模板上线前；
- 用户反馈「打开慢」；
- 改动了资源加载方式（字体、图片、脚本）后；
- 每次大版本发布前做一次回归。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 页面地址或构建产物 | 待测对象 | 必须有 |
| 真实使用场景 | 设备、网络、访问者分布 | 未指定时按「中端手机 + 4G」作为基线 |
| 现有监控数据 | RUM / 报表 | 没有则标注「实验室数据，需上线后复核」 |

## 执行步骤

1. **定基线**：测试环境、设备档位、网络档位、是否登录、是否冷缓存，写清楚。
2. **跑工具**：Lighthouse / WebPageTest / Chrome DevTools Performance，收集 LCP、INP、CLS、TTFB。
3. **看瀑布图**：定位关键请求链（谁阻塞了首屏渲染）。
4. **列资源账本**：每项资源的体积、类型、是否首屏必需、是否可延迟。
5. **定问题**：按「阻塞首屏 → 影响交互 → 影响体积」排序。
6. **给优化动作**：每条动作标注预期收益、风险与验证方式。
7. **定回归线**：把关键指标写成阈值，纳入发布检查。

## 指标与阈值

| 指标 | 含义 | 良好 | 需改进 |
|------|------|------|---------|
| LCP | 最大内容元素渲染 | ≤ 2.5s | > 4.0s |
| INP | 交互到响应 | ≤ 200ms | > 500ms |
| CLS | 布局偏移 | ≤ 0.1 | > 0.25 |
| TTFB | 首字节时间 | ≤ 800ms | > 1.8s |
| FCP | 首次内容绘制 | ≤ 1.8s | > 3.0s |

## 优化手段对照

| 症状 | 常见原因 | 优化动作 |
|------|---------|---------|
| LCP 高 | 首屏大图未优化、字体阻塞渲染、CSS 未拆分 | 预加载主图、字体 `font-display: swap`、内联关键 CSS |
| INP 高 | 长任务、事件处理过重、第三方脚本 | 拆分长任务、任务分片、延后第三方脚本 |
| CLS 高 | 图片无尺寸、字体替换跳动、动态插入内容 | 写死宽高比、`size-adjust`、预留占位 |
| TTFB 高 | 服务端渲染慢、缓存缺失 | 缓存、CDN、减少服务端依赖 |
| 体积大 | 未压缩、未 tree-shake、图片格式老 | Brotli、构建期 tree-shake、WebP/AVIF |

## 输出格式

```markdown
## 基线
- 页面：<...>　设备档位：<...>　网络：<...>　冷缓存：是/否

## 指标
| 指标 | 实测 | 阈值 | 判定 |
|------|------|------|------|
| LCP | 3.4s | ≤ 2.5s | 需改进 |

## 资源账本
| 资源 | 体积 | 类型 | 首屏必需 | 建议 |
|------|------|------|---------|------|
| hero.jpg | 1.8MB | 图片 | 是 | 转 AVIF + 预加载 |

## 关键路径
```
HTML → CSS → 首屏图片 → 字体
         ▲ 阻塞 1.2s
```

## 优化清单
| 优先级 | 动作 | 预期收益 | 风险 | 验证方式 |
|--------|------|---------|------|---------|
| P0 | 主图转 AVIF 并预加载 | LCP -1.1s | 低 | 复测 LCP |

## 回归线
- LCP ≤ 2.5s，INP ≤ 200ms，CLS ≤ 0.1，首屏资源 ≤ <体积阈值>
```

## 质量检查清单

- [ ] 基线条件写清楚（设备、网络、冷热缓存）；
- [ ] 指标是工具实测值，不是估计；
- [ ] 优化清单按收益排序，每条有预期值与验证方法；
- [ ] 标注了风险（如缓存失效、字体闪烁）；
- [ ] 给出了可长期执行的回归阈值；
- [ ] 没有把「减少体积」当成目的本身（体积大不等于体验差）。
