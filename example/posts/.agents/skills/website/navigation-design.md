# 导航与目录结构设计（website）

> 设计「用户随时知道自己在哪、下一步去哪」的导航：主导航、次级导航、面包屑、页内目录。

## 用途

- 设计或重构站点层级与导航文案。
- 解决「用户找不到某个页面」「不知道下一步点哪里」。
- 为长页面设计页内目录与锚点。

## 何时使用

- 站点改版、栏目重组时；
- 新增一级栏目时；
- 跳出率高、搜索使用率低时；
- 长文章需要页内导航时。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 页面台账 | 全部页面及其重要度 | 先用 `content-inventory.md` 生成 |
| 用户高频任务 | 用户最常做的事 | 向用户索取，或从搜索词与埋点推断 |
| 现有导航截图 | 当前体验 | 从主题模板读取 |

## 执行步骤

1. **定主线**：选出 3–5 个用户最常完成的任务，作为主导航项（不是按内部组织结构分）。
2. **设计层级**：确保不超过三层；每层都能回答「上面是什么、下面是什么」。
3. **写导航文案**：用用户会用的词，不用内部代号（不用「资源中心」，用「模板下载」）。
4. **放次级导航**：主导航 ≤ 5 项；其余内容放页内导航、面包屑或页脚。
5. **加面包屑**：层级 ≥ 2 的页面显示，首项可回首页。
6. **做页内目录**：长页面（> 5 个二级标题）生成锚点目录，标题层级不跳级。
7. **标注状态**：当前页高亮、悬停态、移动端折叠方式都要说明。
8. **可访问性核对**：见 `accessibility-audit.md` 的 2.4.x 与 3.2.x 准则。

## 设计原则

| 原则 | 做法 | 反例 |
|------|------|------|
| 数量上限 | 主导航 3–5 项 | 12 个平级入口 |
| 用用户语言 | 「定价」「文档」「案例」 | 「解决方案 A」「资源中心」 |
| 位置一致 | 同一导航在所有页面同一位置 | 首页在上、详情页在下 |
| 当前可见 | 当前页高亮 + `aria-current` | 只有悬停变色 |
| 深度可控 | 不超过三层 | 首页 > 一级 > 二级 > 三级 > 四级 |
| 可跳过 | 提供跳到主内容链接 | 键盘用户要先 Tab 过 20 项导航 |
| 有退路 | 面包屑 + 返回上一级 | 深页无路可回 |
| 移动端等价 | 折叠菜单里的内容与桌面端一致 | 移动端缺少某项 |

## 面包屑规范

```text
首页 / 定价 / 企业版
        └── 每个片段可点击回到对应层级
```

- 首项是首页（可带站点名或直接写「首页」）；
- 用 `/` 或 `›` 分隔，不使用 `>`；
- 当前页不可点击，但需要 `aria-current="page"`；
- 不用面包屑代替主导航。

## 输出格式

```markdown
## 用户高频任务
1. <任务 1>　2. <任务 2>　3. <任务 3>

## 目标层级
```
首页
├── 主导航项 1 → /a/  (任务：<...>)
├── 主导航项 2 → /b/  (任务：<...>)
└── 主导航项 3 → /c/  (任务：<...>)
```

## 主导航
| 位置 | 文案 | 指向 | 服务任务 | 次级项 |
|------|------|------|---------|-------|
| 顶部 | <...> | <...> | <...> | <...> |

## 面包屑
| 层级 | 文案 | 链接 |
|------|------|------|
| 1 | 首页 | / |

## 页内目录（长页）
- <H2 标题> → #<锚点>

## 状态与规则
- 当前页：<高亮方式 + aria-current>
- 悬停 / 聚焦：<...>
- 移动端：<折叠方式>，内容与桌面端一致
- 键盘：<Tab 顺序、跳转链接>

## 待确认
- <需要用户拍板的问题>
```

## 质量检查清单

- [ ] 主导航项 ≤ 5，且每项对应一个用户任务；
- [ ] 导航文案是用户语言，不是内部术语；
- [ ] 层级 ≤ 3，深页有面包屑；
- [ ] 当前页有明确高亮与 `aria-current`；
- [ ] 移动端导航内容与桌面端一致；
- [ ] 提供了跳到主内容的机制；
- [ ] 长页面有页内目录且锚点可用；
- [ ] 没有用下拉菜单藏起高频入口。
