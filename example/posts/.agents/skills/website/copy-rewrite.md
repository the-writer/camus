# 页面文案改写（website）

> 把「介绍我们」的页面改成「帮用户做决定」的页面：说清对象、问题、方案与下一步。

## 用途

- 改写首页、关于页、功能页、定价页、FAQ 的文案。
- 统一语气与术语，消除「官腔」。
- 让 CTA（行动号召）明确、唯一、可执行。

## 何时使用

- 站点上线或改版前；
- 转化率低、跳出率高时；
- 内容从技术文档改成面向普通用户时；
- 团队对外文案不统一时。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 现有文案 | 原文 | 必须有 |
| 页面目标 | 这页要用户做什么 | 向用户确认（只有一个 CTA） |
| 目标读者 | 术语能用到什么程度 | 向用户索取 |
| 事实素材 | 数据、案例、客户名、承诺边界 | 缺素材时明确标注「待补」 |

## 执行步骤

1. **定一句话主张**：这页在 10 秒内要让用户明白什么。
2. **写首屏**：H1 + 副标题 + 主 CTA + 一句佐证（数字 / 客户 / 承诺）。
3. **改主体**：按「痛点 → 方案 → 证据 → 常见异议 → 下一步」重排内容。
4. **写 CTA**：一个主动作，配一句降低风险的说明（如「免费试用」「无需信用卡」）。
5. **处理异议**：把 FAQ 与评论区里的疑虑写进页面。
6. **统一术语**：全站同一概念只用一种说法。
7. **删字**：删除形容词堆叠、无主语的「我们」、无法验证的断言。
8. **做可读性检查**：复用 `blog/readability-score.md` 的指标。

## 文案改写模式

| 现状（弱） | 改写（强） | 差别 |
|-----------|-----------|------|
| 「我们提供领先的解决方案」 | 「把每周 6 小时的报表手工工作降到 10 分钟」 | 具体、可验证 |
| 「支持多种数据源」 | 「支持 CSV、PostgreSQL 和 Webhook，接入平均 20 分钟」 | 有边界、有数字 |
| 「深受用户信赖」 | 「2,300 支球队用它排班，其中 94% 的队伍用满一年」 | 可核验 |
| 「立即开始」 | 「创建免费账号，3 步导入排班表」 | 明确下一步与成本 |
| 「我们致力于创新」 | 删掉 | 无信息量 |

## 页面骨架

```markdown
## 首屏
- H1：<一句主张>
- 副标题：<补足「给谁、解决什么、怎么解决」>
- 主 CTA：<动词 + 对象>
- 佐证：<数字 / 客户 / 承诺边界>

## 主体
### 用户的问题
<用户当前的处境，用他们的语言>
### 你的方案
<怎么解决，产品能力对应到上面的问题>
### 证据
<数据、截图、客户原话；标注来源>
### 常见异议
| 异议 | 回答 |
|------|------|
| <贵不贵 / 会不会太难 / 能不能迁移> | <...> |

## 结尾
- 主 CTA（与首屏一致）
- 次要动作：<文档 / 试用 / 联系>
- 风险消除：<无需信用卡 / 随时导出 / 数据归属>
```

## 质量检查清单

- [ ] 首屏 10 秒内能读懂「给谁、解决什么」；
- [ ] 每页只有一个主 CTA，且是动词短语；
- [ ] 所有数字、承诺、客户名都有来源，无法核实的标 `【待核实】`；
- [ ] 没有「领先」「创新」「赋能」等无信息量的形容词堆叠；
- [ ] 异议部分来自真实用户反馈，而不是想象的；
- [ ] 术语全站统一；
- [ ] 改写后长度没有显著变长；
- [ ] 未虚构用户案例、数据或资质。
