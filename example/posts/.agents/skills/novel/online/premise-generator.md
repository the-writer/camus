# 网文选题与金手指设定（novel/online）

> 开坑前产出四件套：一句话卖点、题材标签与读者承诺、金手指（golden finger）及其限制代价、三个备选方向。

## 用途

- 把「想写个网文」的想法变成能支撑日更的写作契约。
- 在开写前把金手指的边界写死，防止写到中途变成万能钥匙。
- 对比多个选题方向，选出最适配自身更新能力与目标读者的一个。
- 为「黄金三章」备料：冲突、金手指、长线目标必须在这一阶段齐备。

## 何时使用

- 开新坑、定选题时；
- 连载中途长线目标跑偏，需要重新锚定时；
- 为系列作统一核心卖点（同一世界观下的后续作品）时；
- 写完前三章仍说不清「读者到底爽在哪」时。

## 创作进度

> 本技能的第一步是进度回顾：下文用 `<source>` 指源目录（`src/` 或 `posts/`）；从 `<source>/.agents/memories/` 与作品数据源汇总「写到哪、写了多少、还差什么」，再进入具体工作。口径与模板见 `AGENTS.md` §5.4。

### 回顾步骤

1. **读记忆**：先读 `<source>/.agents/memories/project.md`、`outline.md`，再按需读 `characters.md`、`world.md`、`continuity.md`、`preferences.md`、`style.md`；目录或文件不存在就跳过，不视为错误。
2. **扫数据**：扫描源目录（`posts/`，不存在则 `src/`）的卷 / 章文件；若存在 `.workshop/`，按 `AGENTS.md` §5.5 读取设定卡、地名、关系与候选条目。
3. **统计**：按下表统计卷 / 章 / 字数、最近更新、伏笔回收、人物与设定条目；所有数值给出「来源」，无法从文件得到时标「未记录」，不估算、不编造。
4. **对齐**：记忆与正文冲突时以正文为准；回顾结论写回 `outline.md`（进度、伏笔）及受影响的类别文件。
5. **输出回顾**：先交付「进度回顾」块，再继续本技能后续的输入与执行步骤。

### 回顾输出

```markdown
## 创作进度回顾
- 当前阶段：<开坑 / 连载中 / 修稿 / 完结>（依据：<...>）
- 上次更新：<日期 / 最新一章>（依据：<...>）

| 项 | 数值 | 来源 |
|---|---|---|
| 卷数 / 章数 | <...> | <...> |
| 已完成章节 | <...> | <...> |
| 总字数 / 章均字数 | <...> | <...> |
| 伏笔 | 埋 <X> / 收 <Y> / 未收 <Z> | <...> |
| 人物 / 地点 / 关系 / 候选 | <...> | <...> |
| `.workshop` 设定卡 | <... / 无> | <...> |

- 当前进度：<写到哪一卷哪一章，主线停在哪>
- 待续事项：<接下来 1–3 件，按优先级>
```

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 灵感 / 素材 | 一句话、一个画面、一个设定 | 必须有（哪怕只有一句） |
| 题材方向 | 玄幻、都市、科幻、历史、游戏、言情等 | 向用户确认；仍缺则给 3 个候选题材 |
| 更新能力 | 日更频率与可持续日产量（常见量级：日更 1 章、章均 2000–3000 字，实际以作者与平台情况为准） | 按「日更 1 章、章均 2000–3000 字」的常见量级假设，并在输出中标注「待用户确认」 |
| 目标读者 | 想写给谁看（男频 / 女频 / 泛读者 / 老读者追更） | 按「有网文阅读习惯的泛读者」假设并说明 |
| 禁区 / 尺度 | 不写什么、需要规避什么 | 向用户确认；未确认前不生成敏感设定 |
| 已有金手指想法 | 已有的系统 / 传承 / 道具构思 | 无则由本技能生成 2–3 个候选 |

## 执行步骤

1. **抓核心画面**：从灵感里找一个具体画面——谁、在哪、正被什么逼着做选择。
2. **定题材标签**：给 3–6 个标签（1 个主标签 + 若干副标签），标签用来对齐读者预期，不是作品简介。
3. **写一句话卖点**：用「<主角身份> 获得 <金手指>，必须在 <外部压力> 下 <行动>，否则 <代价>」的句式。
4. **写读者承诺**：明确读者点进来能得到什么，列 3–5 条可被验证的承诺（爽点类型、节奏、情绪）。
5. **设计金手指**：按「来源 → 能力清单 → 边界 → 代价」四步写，来源限定在系统 / 传承 / 预知 / 重生 / 血脉 / 道具等常见类型。
6. **给金手指设限**：每项能力写明「触发条件 / 次数或冷却 / 误用后果 / 明确不能做什么」。
7. **给金手指定价**：写出代价（寿元、神魂、金钱、关系、暴露风险等）与其累计方式——网文最忌讳无代价的馈赠。
8. **拆爽点承诺**：区分「即时爽点」与「长线伏笔回报」，各列 3 条以上，每条标明兑现位置。
9. **写三个备选方向**：同题材下的三种走向（金手指类型 / 核心目标 / 代价体系至少其一不同），给出优势、风险与适配的更新节奏。
10. **自检**：跑「网文选题自检表」。

## 金手指设计表

| 项 | 内容 |
|---|---|
| 类型 | <系统 / 传承 / 预知 / 重生 / 血脉 / 道具 / 其他> |
| 来源 | <谁给的 / 从哪来的 / 为什么轮到他> |
| 一句话能力 | <读者十秒内能记住的那一句> |
| 能力清单 | <能力 1>：触发 <...>，效果 <...>，限制 <...><br><能力 2>：…… |
| 明确不能做 | <永远不做的 1–3 件事> |
| 触发条件 | <境界 / 情绪 / 场景 / 次数 / 冷却> |
| 代价形式 | <寿元 / 神魂 / 金钱 / 关系 / 暴露风险 / 其他> |
| 代价量级 | <每次扣多少，累计到多少触发后果> |
| 成长路径 | <金手指如何成长，与主角同步还是滞后> |
| 长期风险 | <谁会盯上它 / 代价累积后的后果> |

## 爽点承诺表

| 承诺 | 类型 | 兑现方式 | 兑现位置 | 读者即时反馈 |
|------|------|----------|----------|--------------|
| <...> | 即时爽点 | 打脸 / 升级 / 扮猪吃虎 / 身份揭晓 / 护短 / 复仇 / 其他 | 第 N 章 | <此刻读者得到什么> |
| <...> | 伏笔回报 | <第 N 章埋 → 第 M 章收> | 第 N / M 章 | <延迟满足感> |

> 区分标准：即时爽点当章闭环，读者不回忆前文也能爽；伏笔回报依赖前文铺垫，兑现时会想起第 N 章的那句话。

## 常见爽点类型的写法要点

| 类型 | 核心期待 | 写作要点 |
|------|----------|----------|
| 打脸 | 先被轻视，后被事实推翻 | 轻视要具体（一句台词 + 一个动作），推翻要晚一点但更响；打脸对象与主角必须有可比的落差 |
| 升级 | 实力台阶被跨过 | 跨阶前先给瓶颈，跨阶后立刻给可验证的压制力；不要只报境界名 |
| 扮猪吃虎 | 隐藏实力换取收益 | 隐藏要有代价（被人小看的憋屈 / 错过机会），收益要具体 |
| 身份揭晓 | 真实身份被认出 | 揭晓前给出线索，揭晓对象要是最不该知道的人；揭晓后立刻改变处境 |
| 护短 | 有人替主角出头 | 被护者要值得护，护者的行为要有身份依据；不能靠临时觉醒 |
| 复仇 | 旧账被清算 | 复仇对象与主角必须有可量化的旧账；清算方式要超出对方预期 |

## 网文选题自检表

| 检查 | 通过标准 |
|---|---|
| 卖点可复述 | 不看文档，读者能说出「谁 + 靠什么 + 干什么」 |
| 金手指有边界 | 至少 1 条「明确不能做」+ 1 项可计量的代价 |
| 代价可结算 | 代价能直接抄进「代价累计表」，不是「有点累」 |
| 长线目标可连载 | 目标足够支撑数十万字，不是一集能解决的事 |
| 爽点类型多样 | 承诺表不全是同一种打脸 |
| 承诺可验证 | 每条承诺都能对应到具体章节的行为 |
| 三方向真不同 | 金手指或代价体系不同，不是换个人名 |
| 无平台硬编码 | 未编造平台规则、榜单、订阅量或作者轶事 |

## 质量检查清单

- [ ] 一句话卖点同时含「主角 / 金手指 / 外部压力 / 行动 / 代价」；
- [ ] 题材标签能一句话说清「这是哪一类书」，不是形容词堆叠；
- [ ] 金手指写了「明确不能做」与代价量级，而非「有副作用」这类空话；
- [ ] 代价可被累计（能抄进代价累计表），且随收益同步变重；
- [ ] 爽点承诺区分了即时爽点与伏笔回报，且都有兑现位置；
- [ ] 三个备选方向在金手指或代价体系上真正不同；
- [ ] 所有量级写成「常见量级 / 参考区间」，未编造平台数据、榜单或作者轶事；
- [ ] 未虚构「某畅销书就是这样写的」这类来源。
