# 人物档案与生活细节（novel/simple）

> 建立可持续维护的人物档案：动机链、功能性关系网、生活细节清单与语言特征，并跑一致性检查。

## 用途

- 让人物有可演的行为逻辑，而不是作者推动剧情的工具。
- 把「人物」落到具体生活上：职业、居住、习惯、身体特征、钱与通勤——细节能反过来生成故事。
- 在长篇里保持人物一致，避免「前后不一样」。
- 让不同的人说话听得出区别，且差异有理由（年龄、地区、职业、亲疏）。
- 排查动机断裂：人物为什么这么做说不通。

## 何时使用

- 开写前建立人物档案；
- 写到人物行为「不像他会做的」时；
- 需要给配角加戏份、或合并功能重复的角色时；
- 校对阶段检查人物设定与正文的矛盾。

## 创作进度

> 本技能的第一步是进度回顾：从 `.agents/memories/` 与作品数据源汇总「写到哪、写了多少、还差什么」，再进入具体工作。口径与模板见 `AGENTS.md` §5.4。

### 回顾步骤

1. **读记忆**：先读 `.agents/memories/project.md`、`outline.md`，再按需读 `characters.md`、`world.md`、`continuity.md`、`preferences.md`、`style.md`；目录或文件不存在就跳过，不视为错误。
2. **扫数据**：扫描源目录（`posts/`，不存在则 `src/`）的篇 / 章文件；若存在 `.workshop/`，按 `AGENTS.md` §5.5 读取设定卡、地名、关系与候选条目。
3. **统计**：按下表统计篇 / 章 / 字数、最近更新、伏笔回收、人物与设定条目；所有数值给出「来源」，无法从文件得到时标「未记录」，不估算、不编造。
4. **对齐**：记忆与正文冲突时以正文为准；回顾结论写回 `outline.md`（进度、伏笔）及受影响的类别文件。
5. **输出回顾**：先交付「进度回顾」块，再继续本技能后续的输入与执行步骤。

### 回顾输出

```markdown

- 当前阶段：<开坑 / 连载中 / 修稿 / 完结>（依据：<...>）
- 上次更新：<日期 / 最新一章>（依据：<...>）

| 项 | 数值 | 来源 |
|---|---|---|
| 篇数 / 章数 | <...> | <...> |
| 已完成章节 | <...> | <...> |
| 总字数 / 章均字数 | <...> | <...> |
| 伏笔 | 埋 <X> / 收 <Y> / 未收 <Z> | <...> |
| 人物 / 地点 / 关系 / 候选 | <...> | <...> |
| `.workshop` 设定卡 | <... / 无> | <...> |

- 当前进度：<写到哪一部分哪一章，主线停在哪>
- 待续事项：<接下来 1–3 件，按优先级>
```

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 故事核 / 一句话梗概 | 人物所处的冲突 | 必须有；缺失时先做 `premise-generator.md` |
| 已有正文片段 | 出现过的人物、称呼、关系、细节 | 扫描输入材料抽取，抽取不到的标注「待补」 |
| 人物功能 | 主角 / 对手 / 盟友 / 镜子 / 门槛 | 从梗概推断并与用户确认 |
| 时代与地域 | 影响生活细节、职业与制度细节 | 未指定时按「当代现实向」假设并说明 |
| 职业领域 | 需要写实的行业或生活领域 | 向用户确认；未确认时只写通用生活细节，不写具体行业规程 |

## 执行步骤

1. **列人物**：从正文抽取所有有名有姓的人物与代称，标注出场次数与所属场景。
2. **分配功能**：标注每人承担的叙事功能（主角 / 对手 / 盟友 / 导师 / 镜子 / 门槛 / 施压者），没有功能的角色列入合并或删除建议。
3. **填动机链**（每个主要人物）：外在目标、内在需求、恐惧、错误信念、秘密、代价——六项缺一不可，缺项写「待补」。
4. **写关系网**：用「A 想要 B 给的 / A 怕 C / A 欠 B / A 需要 B 不知道的」这类**功能性描述**，不写「A 是 B 的朋友」。
5. **填生活细节清单**：职业、居住、习惯、身体特征（另可补钱与通勤通讯、医疗与制度、家庭结构与称谓、季节与气候）。每条细节后附一行「能生出的故事」，答不上来的删掉。
6. **定语言特征**：语速与句长、常用词与口头禅、称谓习惯、方言或行话、回避与沉默方式、情绪外露方式。
7. **跑一致性检查**：对照正文找出行为与档案冲突处，逐条给出改法。
8. **输出档案表**与合并 / 删除建议。

## 动机链模板

```text
外在目标：<可被外部观察的目标，别人看得见他在追什么>
内在需求：<他自己说不清、但真正缺的东西>
恐惧    ：<最怕发生的那件事>
错误信念：<他坚信、但站不住脚的判断>
秘密    ：<瞒着别人的事，一旦暴露会怎样>
代价    ：<不改变信念就要失去的东西>
转变触发：<哪个具体事件逼他承认信念是错的>
新常态  ：<转变之后他成了什么样的人>
```

## 关系网写法

用**功能**描述关系，不用**标签**描述关系：

| 标签写法（不可用） | 功能写法（可用） |
|---|---|
| A 和 B 是朋友 | A 需要 B 给 B 说不出口的勇气；B 需要 A 提供的钱 |
| A 是 B 的敌人 | A 怕 B 手里那份记录；B 需要 A 别把事情闹大 |
| A 是 B 的同事 | A 要 B 替自己顶班；B 要 A 承认流程是他改的 |

附加要求：关系必须**双向且不对称**——A 要 B 给的 ≠ B 要 A 的。

## 生活细节清单

| 类别 | 要写到什么程度 | 能生出的故事（示例问法） |
|---|---|---|
| 职业 | 术语、流程环节、收入量级、工作时间 | 哪一步流程会让他迟到、丢单、被扣钱？ |
| 居住 | 楼层、户型、噪音、采光、邻里关系 | 邻居听见了什么？他为什么不肯搬走？ |
| 习惯 | 小动作、固定时段、消费与 wasting 习惯 | 这个习惯在什么场合会暴露他？ |
| 身体特征 | 身高、体型、伤病、视力听力、衰老痕迹 | 哪句台词会因为听力问题没听清？ |
| 钱 | 收入量级、固定支出、可动用余额 | 这笔钱够不够撑到发工资那天？ |
| 通勤与通讯 | 路程耗时、交通方式、消息到达时差 | 谁会因为一条没能及时收到的消息做错决定？ |
| 医疗与制度 | 病程限制、请假与报销等手续常识 | 手续卡在哪一步？他为什么不肯去办？ |
| 家庭结构与称谓 | 谁跟谁住、怎么称呼、谁不在了 | 为什么在这个称呼上他停顿了一下？ |
| 季节与气候 | 当季气温、衣物、作息、作物 | 天气怎样改变了他的计划？ |

> 每条细节写成「<具体描述> ｜ 来源：<正文设定 / 推断 / 待核实> ｜ 能生出的故事：<...>」。来源为「推断」的必须标出，作者未确认前不能当定论用。

## 语言特征表

| 维度 | 写法 | 检验 |
|---|---|---|
| 语速与句长 | 短促 / 拖长；单句多 / 从句多 | 遮住人名能认出是谁吗 |
| 常用词与口头禅 | 具体到可模仿的词或句式 | 换个角色说还成立吗 |
| 称谓习惯 | 对长辈 / 平辈 / 下属分别叫什么 | 与关系变化同步过吗 |
| 方言与行话 | 只列真正会出现在口中的词 | 换角色是否失效 |
| 回避与沉默 | 什么话题他不接、怎么岔开 | 沉默是否被写出来 |
| 情绪外露 | 哭 / 骂 / 沉默 / 手上的动作 | 越激动越沉默的人被写对了吗 |

## 一致性检查表

| 检查 | 通过标准 |
|---|---|
| 行为可解释 | 每个关键行为都能追溯到动机链中的某一项 |
| 目标与需求不同 | 外在目标 ≠ 内在需求；相同即人物扁平 |
| 信念驱动决策 | 错误信念能解释至少两次错误决策 |
| 秘密有代价 | 秘密一旦暴露会造成真实损失 |
| 关系非对称 | 每组关系都是双向且不对称的 |
| 配角有功能 | 每个配角至少承担一项功能，否则列入合并或删除 |
| 语言可辨 | 同一场景遮住人名能认出说话人 |
| 细节可生故事 | 每条生活细节都能说出生出哪个冲突；说不出的已删 |
| 细节不打架 | 职业、时间、钱数、称谓、年龄互不矛盾 |

## 质量检查清单

- [ ] 每个主要人物都有完整动机链，缺项标注「待补」而不是留空；
- [ ] 外在目标与内在需求**不同**，相同的一律重写；
- [ ] 错误信念能解释至少两次错误决策；
- [ ] 关系描述里没有出现「朋友」「敌人」这类空标签，且每组关系双向不对称；
- [ ] 生活细节覆盖职业 / 居住 / 习惯 / 身体特征四类，且每条都写得出「能生出的故事」；
- [ ] 语言特征具体到可模仿，遮住人名能认出说话人；
- [ ] 一致性问题都给出了明确处理方式（改动机 / 改行为 / 加过渡三选一）；
- [ ] 涉及真实职业规程、医疗与制度流程的表述保持概括，需核实处标「待核实」，未编造条款与来源。
