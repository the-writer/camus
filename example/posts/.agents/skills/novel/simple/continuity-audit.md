# 生活细节与时间线审查（novel/simple）

> 用「事实台账 + 时间轴 + 职业与制度核查 + 伏笔账本」四张表，检查现实向长篇的内部自洽。

## 用途

- 找出「作者自己记错了」的硬伤：时间、地理、天气、伤势、钱、职业、称谓。
- 检查生活细节是否与人物的处境相称（收入与开销、工时与通勤、伤情与恢复）。
- 检查制度流程是否被一句「办好了」糊过去。
- 排查视角信息越界：人物用了他不可能知道的信息。
- 检查伏笔是否埋了、收了、并且兑现的是同一件事。

## 何时使用

- 每写完一卷 / 每 5–10 万字做一次；
- 出版或连载前终审；
- 读者提出「前后矛盾」反馈时；
- 多线叙事交错的章节写完之后；
- 涉及具体职业、医疗或制度流程的段落写完之后。

## 创作进度

> 本技能的第一步是进度回顾：从 `.agents/memories/` 与作品数据源汇总「写到哪、写了多少、还差什么」，再进入具体工作。口径与模板见 `AGENTS.md` §5.4。

### 回顾步骤

1. **读记忆**：先读 `.agents/memories/project.md`、`outline.md`，再按需读 `characters.md`、`world.md`、`continuity.md`、`preferences.md`、`style.md`；目录或文件不存在就跳过，不视为错误。
2. **扫数据**：扫描源目录（`posts/`，不存在则 `src/`）的篇 / 章文件；若存在 `.workshop/`，按 `AGENTS.md` §5.5 读取设定卡、地名、关系与候选条目。
3. **统计**：按下表统计篇 / 章 / 字数、最近更新、伏笔回收、人物与设定条目；所有数值给出「来源」，无法从文件得到时标「未记录」，不估算、不编造。
4. **对齐**：记忆与正文冲突时以正文为准；回顾结论写回 `outline.md`（进度、伏笔）及受影响的类别文件。
5. **输出回顾**：先交付「进度回顾」块，再继续本技能后续的输入与执行步骤。


## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 全部正文 | 或分卷文本 | 必须有 |
| 人物档案 | 已知设定基线 | 缺失时先做 `character-bible.md` |
| 梗概与主题 | 判断哪些细节属于本故事 | 向用户确认或从正文推断并标注「推断」 |
| 章节顺序 | 叙事顺序 vs 故事时间顺序 | 从正文抽取；无法确定的标注「待核实」 |
| 时代与地域 | 生活细节与制度细节的适用范围 | 未指定时按「当代现实向」假设并说明 |

## 执行步骤

1. **建事实台账**：逐章抽取可被验证的事实——时间、地点、天气、伤势、金钱、职业、称谓、年龄，以及通勤通讯、家庭结构。
2. **建时间轴**：把事件按「故事时间」排序，标出叙事位置（章节号）与时间跨度。
3. **交叉比对**：同一实体在不同章节的记录是否冲突。
4. **查职业与制度细节**：术语、流程、收入量级、手续、交通与通讯时延是否自洽。
5. **查视角信息越界**：角色是否用了他不可能知道的信息（作者漏给了读者，或漏给了角色）。
6. **查伏笔账本**：每个伏笔是否有埋点与回收点，回收是否兑现了埋点承诺的内容。
7. **分级输出**：致命 / 显要 / 轻微，并给到「改哪一章的哪一句」的改法。

## 事实台账

| 实体 | 属性 | 首次出现（章） | 再次出现（章） | 一致？ | 处理 |
|------|------|--------------|--------------|-------|------|
| <角色 A> | 左手受伤 | 第 3 章 | 第 12 章 | 否 | <改第 3 章为右手 / 改第 12 章> |

必须逐章抽取的属性：

| 属性 | 抽取要点 |
|---|---|
| 时间 | 季节、月份、星期、时刻；「三天后」与前文时长相加是否成立 |
| 地点 | 城市与场所；两地之间的耗时是否可信 |
| 天气 | 气温、降水；是否与季节、衣物、作息一致 |
| 伤势与健康 | 部位、严重程度、恢复周期、慢性病限制 |
| 金钱 | 收入量级、固定支出、余额；是否够撑到下一笔收入 |
| 职业 | 术语、流程环节、工时、收入与生活水准是否匹配 |
| 称谓 | 亲属、同事、上级之间的称呼是否随关系变化 |
| 年龄 | 出生年份推算、辈分、退休或入学年龄 |
| 通勤与通讯 | 路程耗时、交通方式、消息到达的时差 |
| 家庭结构 | 谁与谁同住、谁不在了、户口与照护安排 |

## 时间轴

| 故事时间 | 事件 | 叙事位置 | 跨度推算 | 冲突提示 |
|---------|------|---------|---------|---------|
| D+0 | <...> | 第 1 章 | 当日 | — |

推算要求：跨章事件用「上一场结束时间 + 事件本身耗时 + 路程耗时 + 手续耗时」逐项累加，得出故事时间；与正文写的时刻不一致即记一条问题。

## 职业与制度细节核查

| 维度 | 核查什么 | 常见断裂 |
|---|---|---|
| 职业流程 | 术语是否用对、环节顺序是否颠倒 | 说出不属于该岗位的话；流程少一步或多一步 |
| 工时与收入 | 工时、加班、薪资量级与生活水准是否匹配 | 月薪与租房、吃饭、随礼的支出打架 |
| 制度手续 | 请假、报销、落户、学籍、就医、办证的常识流程 | 手续被一句「办好了」跳过，或无凭据就拿到了结果 |
| 交通与通讯 | 通勤耗时、跨区耗时、消息到达时差 | 一条消息瞬间跨越半座城；深夜也能随时找到人 |
| 家庭与称谓 | 亲属关系、称谓随关系变化 | 长辈与晚辈叫法前后不一；分家后仍用旧称 |
| 季节与气候 | 衣物、取暖、作物、日照、作息 | 北方冬天穿短袖；梅雨季晾不了衣服 |
| 医疗与健康 | 恢复周期、日常限制、用药与随访 | 断骨下周就能跑；慢性病人毫无忌口 |

> 事实纪律：涉及真实制度、法律、医疗与职业规程时，只按「现实常见做法」概括书写，**不编造条文编号、具体条款与来源**；把握不准处标注「需核实」并列入待办，不凭空补齐。

## 视角信息越界

限知视角下，视角人物不能知道：

- 他不在场时发生的事；
- 别人心里想什么（除非有可见的行为依据）；
- 只有叙述者（或另一个视角人物）看到的信息；
- 尚未发生的事（用「他没想到」暗示未来是可以的，用「他知道了」不行）。

排查动作：

1. 找出文中所有「他知道 / 她明白 / 他意识到 / 他看得出」这类句子；
2. 逐句追问信息来源：在场？听见？看见？被告知？想过？
3. 无来源的，标为越界；
4. 作者若要给读者信息而不给角色，用**独立场景**的叙述者视角、他人转述或书面材料，不要在同一场景里混用限知视角。

## 伏笔账本

| 编号 | 埋点 | 承诺的内容 | 回收点 | 兑现？ | 状态 |
|------|------|-----------|--------|-------|------|

判定：回收的内容必须与埋点承诺的是**同一件事**；「差不多相关的另一件事」算未兑现。长期不回收的，要么改，要么明确标注为留白。

## 严重度分级

| 级别 | 定义 | 处理 |
|---|---|---|
| 致命 | 改变情节逻辑的硬伤（人死了又出现、时间倒流、当天不可能在两地） | 必须改 |
| 显要 | 削弱可信度的矛盾（同一晚两个场景、伤口位置不一致、收入与开销打架） | 尽量改 |
| 轻微 | 表述不一致（同一物两个称呼、天气细节不同） | 可留，或统一措辞 |

> 风格偏好不是连续性错误；不要把「我更想这么写」记成问题条目。

## 质量检查清单

- [ ] 台账覆盖了时间、地点、天气、伤势、金钱、职业、称谓、年龄，以及通勤通讯与家庭结构；
- [ ] 每个问题都标注了级别、位置与建议改法；
- [ ] 建议改法明确到「改哪一章的哪一句」；
- [ ] 时间轴上的跨度是逐项累加推出来的，不是照抄正文；
- [ ] 职业与制度细节只按现实常见做法概括书写，需核实处已列入待核实清单，未编造条款与来源；
- [ ] 视角信息越界单独列出，每条都指出了缺失的信息来源；
- [ ] 伏笔账本中所有伏笔都有状态（已回收 / 留白 / 待埋），并核对了「承诺」与「兑现」是不是同一件事；
- [ ] 没有把风格偏好当成连续性错误。
