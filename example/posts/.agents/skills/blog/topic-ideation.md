# 选题灵感库（blog）

> 从站点定位、读者画像与既有内容中，批量产出可执行的选题清单。

## 用途

- 为博客 / 专栏生成一批**互不重叠、可落地**的选题。
- 把「我想写点什么」变成一张带优先级、角度、切入点的选题表。
- 补齐内容日历，避免重复选题与自说自话。

## 何时使用

- 新站开站，需要首批 10–30 个选题；
- 更新频率下降，需要从既有内容延伸出新选题；
- 手里有素材（笔记、代码、经历）但不知道能写成什么；
- 需要判断某个想法**值不值得写**。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 站点定位 | 主 SUMMARY.md 的 `title` / `subtitle` / `description` | 必须先向用户索取 |
| 读者画像 | 谁读、他们关心什么、读到这里能带走什么 | 向用户索取 1–2 句即可 |
| 既有文章 | `posts/` 下已有文章标题（用于去重） | 自行扫描目录 |
| 素材池 | 用户的经历、笔记、收藏、代码 | 没有则从站点定位推导 |

## 执行步骤

1. **锚定定位**：读完主 `SUMMARY.md`，用一句话写出「本站为谁解决什么问题」。
2. **盘点存量**：列出 `posts/` 下已有文章标题，按「主题 / 形式」归类，标出**已覆盖**的主题簇。
3. **生成候选**：按下列 5 个杠杆各产出一批，每个杠杆至少 3 条：
   - **经验杠杆**：我踩过的坑、做过的事、失败的尝试；
   - **疑问杠杆**：读者常问但文章没答的问题（从站内搜索词、评论、群聊里找）；
   - **对比杠杆**：A 与 B 的差别（工具之间、做法之间、时期之间）；
   - **拆解杠杆**：把一个大主题拆成「原理 / 步骤 / 坑 / 替代方案」；
   - **时效杠杆**：版本更新、事件热点、行业变化带来的复盘。
4. **去重**：与第 2 步的主题簇比对，剔除重复；与本期其它候选比对，剔除同质。
5. **打分**：用下表给每个候选打分（1–5 分），保留 ≥ 12 分的候选。
6. **排序**：输出前 5 个「最该先写」的选题，并说明理由。

## 评分表

| 维度 | 1 分 | 5 分 |
|---|---|---|
| 需求强度 | 读者不会主动找 | 读者反复问 / 反复搜 |
| 个人优势 | 别人写也一样 | 只有你能写（有实测、有踩坑、有数据） |
| 可执行性 | 需要一周以上才能动笔 | 两小时内能写出完整初稿 |
| 差异化 | 网上已有大量同质内容 | 角度或结论与既有内容明显不同 |
| 长尾价值 | 写完即忘 | 有持续搜索价值，可被反复引用 |

## 输出格式

```markdown
## 站点定位
<一句话：为谁解决什么问题>

## 选题清单
| # | 选题 | 读者痛点 | 切入角度 | 需求 | 优势 | 可执行 | 差异 | 长尾 | 总分 | 建议篇幅 |
|---|------|---------|---------|-----|-----|-------|-----|-----|-----|---------|
| 1 |  ...  |  ...    |  ...    |  3  |  5  |   4   |  4  |  3  | 19  | 2000 字 |

## 优先写这 5 个
1. <选题> —— <一句话理由>
...
## 已有内容覆盖情况
- 已覆盖：<主题簇>
- 空白区：<主题簇>
```

## 质量检查清单

- [ ] 每个选题都能写成一句话的「读者收益」，而不是一个话题名词；
- [ ] 清单内部没有两个选题在讲同一件事；
- [ ] 与 `posts/` 已有文章无重复；
- [ ] 至少 3 个选题来自读者视角（疑问 / 对比），不是纯自嗨；
- [ ] 每个选题标了建议篇幅与预计难度；
- [ ] 没有虚构数据、读者调研结论或「大家都关心」这类未经验证的断言。
