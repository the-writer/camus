# 同类文章查找与内链（blog）

> 在站内已有内容中找出「同一话题」的旧文，判断是补内链、合并，还是干脆另写一篇。

## 用途

- 写新稿前查重，避免同一件事写两遍。
- 给旧稿补内链，把散落的内容串成体系。
- 发现结构性问题：哪些主题被写了五遍，哪些只被提了一句。
- 为「同类查找」需求给出可信的对照清单。

## 何时使用

- 新选题确定后、动笔前；
- 内容重构 / 合并旧文时；
- 需要为某篇文章找「延伸阅读」时；
- 做站点内容盘点时。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 新主题或关键词 | 要找同类的对象 | 必须有 |
| 站内文章清单 | 标题、路径、摘要、标签 | 扫描 `posts/`（或 `src/`）生成 |
| 站点主题边界 | 什么算「同类」 | 从主 `SUMMARY.md` 推断 |

## 执行步骤

1. **建索引**：扫描内容目录，抽取每篇文章的标题、首段摘要、标签、目录层级，形成索引表。
2. **多路召回**：对目标主题分别用以下方式检索，各取前 10 条：
   - 关键词包含（标题 / 正文出现目标词）；
   - 语义近义（同义表述、近义场景）；
   - 主题簇（同目录、同标签、同系列文章）；
   - 结构相似（同样式的问题—原因—方案结构）。
3. **合并打分**：每条候选按 `主题重合度 / 视角差异 / 时效性 / 可引用性` 打 1–5 分。
4. **分三类归档**：
   - **可内链**：主题相同但视角/深度不同 → 在新文中引用并说明关系；
   - **需更新**：主题相同且内容过时 → 建议先更新旧文，或标注旧文为已废弃；
   - **重复**：主题与结论几乎一致 → 建议合并或改为「更新版」，必要时重定向。
5. **给内链建议**：列出「文章 A ← 新文 B」的对，并写明锚文本（锚文本要能独立说明目标内容）。
6. **给结论**：新稿是否值得独立成文。

## 判定标准

| 关系 | 特征 | 处理 |
|---|---|---|
| 互补 | 同一话题，不同层面（入门 vs 进阶、观点 vs 实操） | 互相内链 |
| 递进 | 同一系列的前后篇 | 双向链接 + 「上一篇 / 下一篇」 |
| 更新 | 同一话题，新版本信息更全 | 更新旧文并保留旧链接 |
| 重复 | 主张、论据、结论高度一致 | 合并 / 改写为不同角度 |
| 蹭热度 | 蹭同一关键词但回答不同问题 | 不内链，避免稀释 |

## 输出格式

```markdown
## 站内索引摘要
- 文章总数：<...>　目录数：<...>　主要主题簇：<...>

## 同类候选
| 文章 | 路径 | 与目标主题的关系 | 重合 | 视角差 | 时效 | 可引用 | 处理 |
|------|------|-----------------|-----|-------|------|--------|------|
| <标题> | <路径> | 互补 | 3 | 5 | 4 | 5 | 内链 |

## 内链建议
- 新文 → 《<旧文标题>》：<锚文本> —— <放在哪一段、为什么>
- 《<旧文标题>》 → 新文：<锚文本>

## 重复内容处理建议
- <文章> 与 <文章>：<合并 / 更新 / 保留并加差异说明>，理由：<...>

## 结论
<新稿是否值得独立成文；若值得，给出与旧文区别的角度>
```

## 质量检查清单

- [ ] 索引覆盖了内容目录下所有 `.md`（含子目录）；
- [ ] 召回用了多种方式，不是只靠关键词匹配；
- [ ] 每条候选都给了关系类型与处理动作；
- [ ] 内链锚文本能独立表达目标内容，不使用「点击这里」「这篇文章」；
- [ ] 重复判定有依据（主张 / 论据 / 结论对比），不凭印象；
- [ ] 没有建议把两篇文章强行合并（除非确实高度重复）。
