# 文章结构大纲（blog）

> 把一个选题拆成「读者能跟得上」的小节骨架，并给每节配写作要点与证据需求。

## 用途

- 在动笔前确定文章骨架，避免写着写着跑题。
- 给每个小节明确「写什么、写到什么程度、需要什么材料」。
- 评估文章是否结构失衡（例如背景写了三屏、正文只有一段）。

## 何时使用

- 已有选题，需要搭结构；
- 稿件「读起来乱」「中段塌陷」，需要重构；
- 需要把长文拆成系列或把多篇合成一篇。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 选题 / 一句话主张 | 这篇文章要让读者记住什么 | 向用户确认 |
| 读者与前置知识 | 读者已经知道什么 | 向用户索取 1 句 |
| 素材与证据 | 截图、日志、数据、代码、引用 | 列出「需要补」的清单交给用户 |

## 执行步骤

1. **写主张句**：用一句话写出文章主张（不是话题，是可被反驳的判断）。主张句决定全文骨架。
2. **定读者起点**：明确读者读这篇之前知道什么、读完之后能做到什么。
3. **选骨架**：按主张匹配结构类型（见下表），不要默认「背景—过程—总结」。
4. **切小节**：每节写清「本节要解决的问题」；一节只解决一个问题。
5. **配要点**：每节列 2–4 条写作要点，每条标明需要什么证据。
6. **埋钩子**：在关键小节前标注过渡句要引出的下一个问题。
7. **体检**：跑「结构自检表」，不通过就改骨架而不是硬写。

## 常用骨架

| 骨架 | 适用 | 顺序 |
|---|---|---|
| 问题—原因—方案 | 教程、故障复盘 | 现象 → 根因 → 解法 → 验证 |
| 结论先行（倒金字塔） | 评测、观点、汇报 | 结论 → 依据 → 细节 → 例外 |
| 时间线 | 复盘、行业观察 | 起点 → 转折 → 现在 → 展望 |
| 教程（任务导向） | 操作类 | 前置条件 → 步骤 → 验证 → 排错 |
| 问答 | FAQ、答疑 | 问题 → 直接答案 → 展开 → 相关问题 |
| 对比 | 选型、比较 | 结论 → 维度表 → 逐维度对比 → 选型建议 |
| 案例研究 | 项目复盘 | 背景 → 目标 → 做法 → 结果 → 复盘 |

## 结构自检表

| 检查 | 通过标准 |
|---|---|
| 主张可反驳 | 主张句里没有「很重要」「很有用」这类无信息量词 |
| 小节单一职责 | 每节能用一句话说清它解决什么 |
| 顺序有理由 | 能解释为什么 A 在 B 之前（依赖 / 因果 / 由浅入深） |
| 无背景墙 | 背景信息不超过全文 15%，且与主张直接相关 |
| 证据到位 | 每条要点都标了「需要什么材料」，没有凭空断言 |
| 结尾有落点 | 结尾对应主张，而不是重复摘要 |

## 输出格式

```markdown
## 主张
<一句话，可被反驳>

## 读者起点与终点
- 起点：<读者已知>
- 终点：<读者能做到>

## 骨架
<骨架类型> —— 选择理由：<...>

## 小节大纲
### 1. <小节标题>
- 解决：<本节回答的问题>
- 要点：
  - <要点 1>（证据：<需要什么>）
  - <要点 2>（证据：<需要什么>）
- 过渡：<下一节引出的问题>

### 2. ...

## 需要补的材料
- <材料 1>（用于第 N 节）
## 暂不写进本篇
- <被砍掉但值得单独成篇的内容>
```

## 质量检查清单

- [ ] 主张句能被反驳，不是话题描述；
- [ ] 每个小节只有一个职责，没有「顺便讲一下」；
- [ ] 小节顺序的理由写了出来，不是随手排的；
- [ ] 所有需要外部证据的地方都标了来源类型（数据 / 截图 / 代码 / 引用）；
- [ ] 背景信息占比可控；
- [ ] 结尾有明确落点，且与主张呼应；
- [ ] 被砍掉的内容有去处（列入「暂不写进本篇」），不凭空消失。
