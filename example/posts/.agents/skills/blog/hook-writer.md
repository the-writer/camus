# 标题、开头与摘要（blog）

> 产出「标题候选 + 开头前 3 句 + 摘要 + 导语」的成套文本，并解释每一版的取舍。

## 用途

- 解决「标题写不出」「开头三句抓不住人」「摘要像目录」的问题。
- 一次产出多个候选，让作者做**选择**而不是从零写。
- 为列表页、RSS、社交分享统一准备短文本。

## 何时使用

- 稿件完成，需要标题与摘要；
- 内容发布前需要多平台适配文本；
- 标题点击率低，需要换一批思路；
- 读者反馈「开头看不下去」。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 文章正文或大纲 | 主张与关键信息 | 必须有大纲或正文 |
| 目标读者 | 影响措辞的专业度 | 向用户确认 |
| 发布渠道 | 站内列表页 / RSS / 社交 / 邮件 | 渠道未知时按站内 + RSS 准备 |
| 语气基线 | 站点既有风格 | 扫描 `posts/` 已有文章推断 |

## 执行步骤

1. **提取内核**：从正文提炼「主张 + 收益 + 差异」三要素，各一句话。
2. **写标题候选 5 个**，覆盖 5 种不同角度（不要 5 个同义改写）：
   - 收益型：读完能做什么；
   - 痛点型：先说读者的困境；
   - 反直觉型：打破一个默认认知；
   - 结果型：给一个具体数字或场景；
   - 关键词型：保留读者会搜的词（利于检索）。
3. **写开头 3 句**：必须包含「具体场景 / 冲突 / 承诺」三件事之一以上，且不出现「本文将介绍」这类空转句式。
4. **写摘要**：50–150 字，包含主张与读者收益，不复述目录。
5. **写导语（可选）**：文章较长（> 3000 字）时补一段 2–3 句的导语，说明为什么现在值得读。
6. **做对比说明**：每个候选标注「适合什么场景 / 风险」。
7. **给推荐**：明确推荐一个标题 + 一个开头，并说明理由。

## 开头自检

| 检查 | 通过标准 |
|---|---|
| 有具体名词 | 首句出现具体的人、事、物、数字或场景，不是抽象概念 |
| 无空转开头 | 不以「在当今……」「随着……发展」「本文将……」开头 |
| 有张力 | 存在一个问题、冲突或反常识判断 |
| 承诺明确 | 读者知道读完能得到什么 |
| 与正文一致 | 开头承诺的内容正文确实给了 |

## 输出格式

```markdown
## 内核
- 主张：<...>
- 收益：<...>
- 差异：<...>

## 标题候选
| # | 标题 | 角度 | 适合场景 | 风险 |
|---|------|------|---------|------|
| 1 |  ...  | 收益型 | 搜索流量 | 偏平 |

推荐：<标题 3> —— <理由>

## 开头（前 3 句）
> <句 1>

> <句 2>

> <句 3>

## 摘要（50–150 字）
<摘要正文>

## 导语（长文可选）
<2–3 句>

## 渠道适配
- 站内列表页：<短标题 / 一句话说明>
- RSS 摘要：<...>
- 社交分享：<...>
```

## 质量检查清单

- [ ] 5 个标题角度互不相同，不是同义改写；
- [ ] 推荐项已明确给出，不是让用户自己挑；
- [ ] 开头首句含具体名词或场景；
- [ ] 摘要说明「读者能得到什么」，不是小节列表；
- [ ] 标题与正文一致，没有标题党；
- [ ] 中英混排的空格与标点符合《中文文案排版指北》；
- [ ] 未使用「最」「第一」「必看」等无信息量的夸张词。
