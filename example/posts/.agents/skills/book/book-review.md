# 书评写作（book）

> 写一篇「有立场、有证据、对读者有用的」书评，而不是简介或读后感流水账。

## 用途

- 为一本（或一组）书写书评。
- 把读后感转成结构化、可发布的文字。
- 在书单页中给出 200 字左右的短评。

## 何时使用

- 读完一本书需要输出时；
- 维护书单 / 读书专题时；
- 为推荐活动或栏目供稿时。

## 输入

| 输入 | 说明 | 缺失时 |
|---|---|---|
| 书与版本 | 标题、作者、译者、版次 | 必须有 |
| 阅读记录 | 笔记、卡片、摘录 | 缺失时先做 `key-idea-extractor.md` |
| 读者定位 | 写给谁看 | 向用户确认；默认面向「读过类似书的普通读者」 |
| 字数 | 短评 / 长评 | 未指定时按 800–1500 字 |

## 执行步骤

1. **定立场**：这本书最值得说的一件事是什么（好在哪 / 差在哪 / 适合谁 / 不适合谁）。
2. **先给结论**：开头 3 句内说清结论与推荐对象。
3. **给证据**：至少两处具体内容（章节、案例、数据、原文短引）支撑判断。
4. **写「对谁有用」**：明确「如果你关心 X，值得读；如果只想要 Y，可以跳过」。
5. **写保留意见**：真诚指出局限，但不要为了显得深刻而贬低。
6. **与同类书对照**：与 1–2 本同类书比一句（见 `comparable-books.md`）。
7. **给行动**：读它之前该知道什么；读完可以做什么。
8. **按体裁裁剪**：短评只保留结论 + 一个证据 + 一个适用人群。

## 结构

```markdown
## 结论
<两三句：这本书是什么、值不值得读、适合谁>

## 证据
- <证据 1：具体章节 / 案例 / 数据>
- <证据 2：...>

## 它的写法
<作者如何论证：结构、语气、案例方式；可以对比同类书>

## 局限
<一个真实局限 + 对谁有影响>

## 适合 / 不适合
- 适合：<...>
- 不适合：<...>

## 读前 / 读后
- 读前：<需要知道的背景>
- 读后：<可以接着读什么 / 做什么>
```

## 短评模板（150–250 字）

```markdown
<书名>：<一句话定位>。
<最有价值的一点，附一个具体证据>。
<一个保留>。
适合 <谁>；如果你 <某种需求>，<另一本书/其他建议> 更合适。
```

## 写作要点

| 要点 | 说明 |
|------|------|
| 判断而非复述 | 复述内容是简介；书评要给判断 |
| 证据具体 | 「第 7 章的制造业案例」优于「举了很多例子」 |
| 面向读者 | 明确「你」是谁、为什么与你有关 |
| 不装中立 | 有偏好很正常，但要有理由 |
| 不剧透关键转折 | 除非专门写剧透 |
| 尊重作品 | 可以批评，但针对论证与效果，而非作者人品 |
| 不虚构 | 引用、数据、版本必须可核对 |

## 质量检查清单

- [ ] 开头 3 句内给出结论与推荐对象；
- [ ] 至少两处具体证据，位置可核对；
- [ ] 明确写出适合与不适合的人群；
- [ ] 局限是真实的，不是为了平衡而套话；
- [ ] 与同类书的对照有一句具体差异；
- [ ] 没有编造引文、数据或出版信息；
- [ ] 未泄露不该剧透的情节；
- [ ] 结论与正文证据一致。

## 参考资料

- [Andy Matuschak 的常青笔记](https://notes.andymatuschak.org/) —— 「这本书改变了我的什么」式写作范式
- [Zettelkasten.de：介绍](https://zettelkasten.de/introduction/) —— 观点与来源的组织
- [豆瓣读书](https://book.douban.com/) —— 版本信息与同类书参考
- [Open Library](https://openlibrary.org/) —— 出版信息核对
- [诺贝尔文学奖](https://www.nobelprize.org/prizes/literature/) —— 经典作品背景资料
