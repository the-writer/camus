# Camus 创作助手 · 技能总纲

> 本文件安装在**项目根**的 `.agents/AGENTS.md`；技能与记忆统一位于项目根 `.agents/`。
> 技能文件按项目类型分目录存放于 `.agents/<type>/`，小说类型再按子类型分目录存放于 `.agents/novel/<subtype>/`；
> 每次任务都必须先读 `.agents/memories/` 记忆、完成「项目类型判定」，再加载对应技能。
> 项目根另有安装时写入的短文件 `AGENTS.md`，只负责提示先读本文件；所有规则以本文件为准。

---

## 0. 强制工作流

> 每次接到写作 / 内容 / 代码类任务，**都按下面流程走**，不得跳步；类型为 `novel` 时额外多一步子类型判定（步骤 1b），并在加载技能前完成一次创作进度回顾（步骤 3b）。

### 步骤 0 · 读取记忆

项目根 `.agents/memories/` 存放跨会话记忆（上次推断出的项目类型、用户偏好、人物与设定、大纲进度等）。

1. 目录存在时，先读其中的 `project.md`（若存在），把它当作上次已确认的项目上下文；`project.md` 缺失、缺少「项目概览」或 `user/` 下没有可用文件时，标记为**需要初始化**，完成步骤 1 / 1b 后执行步骤 1c。
2. 本次任务相关的类别文件（如 `characters.md`、`world.md`、`outline.md`）在进入对应工作前再读；**类型为 `novel` 时先读 `outline.md` 回顾进度与伏笔（流程见步骤 3b）**，不必一次读全。
3. **按需读取用户记忆**：涉及写作、改写、评审、规划、风格调整或需要给方案时，读 `.agents/memories/user/` 下对应用户的文件（默认 `default.md`，见 §5.2.1）；纯事实查询或机械操作可不读。
4. 项目根存在 `.workshop/` 时，小说任务按 §5.5 把它作为创作资产库一并读取；不存在就跳过。
5. 记忆与当前正文 / 用户新指令冲突时，以正文与新指令为准，并在步骤 5 修正记忆。

### 步骤 1 · 读取主 SUMMARY.md，推断项目类型

源目录（`posts/`，若存在则 `src/`）根目录下的 `SUMMARY.md` 是站点元信息的唯一入口，**必须第一个读**。

**项目类型不写在配置里**，由 AI 首次运行时依据下列线索推断：

1. **元信息**：`title` / `subtitle` / `description` 指向的站点性质（文章集 / 产品页 / 工程文档 / 读书 / 文学创作）。
2. **目录结构**：按时间或主题分组的文章 → `blog`；按卷 / 章 / 幕划分 → `novel`；功能页而非文章集 → `website`；含 `docs/` / `api/` → `tech`；以书为单位 → `book`。
3. **正文样本**：读首篇文章 / 首章的标题与开头，确认体裁与读者预期。
4. **兜底询问**：线索不足或证据冲突 → 进入步骤 3（询问用户）。

> 推断完成后，把结果与依据写入 `.agents/memories/project.md`（见 §5），后续运行直接复用。

### 步骤 1b · 判定小说子类型（仅 `novel`）

小说技能按子类型分成三个目录，写作规范差异很大，**必须先判定再加载**：

| 子类型 | 目录 | 适用作品 | 判定线索 |
|---|---|---|---|
| `online` | `.agents/novel/online/` | 中文网络小说、连载爽文 | 「网文 / 连载 / 日更 / 爽文 / 系统流 / 升级流」；长篇连载体量；按等级 / 境界划分战力；按「家族→宗门→大陆」推进 |
| `western-illusion` | `.agents/novel/western-illusion/` | 西方奇幻、史诗奇幻 | 「西幻 / 魔法 / 剑与魔法 / 龙 / 教会 / 公会 / 地下城 / 领主」；有魔法体系、种族与势力设定；冒险旅程式结构 |
| `simple` | `.agents/novel/simple/` | 现实向、人物驱动的普通小说 | 「短篇 / 中篇 / 家庭 / 职场 / 成长 / 日常」；不依赖类型套路；冲突来自人物处境与选择 |

判定规则：

1. **文本推断**：读正文样本（首章 + 若干章），按上表线索判定。类型与子类型都**不写入** `SUMMARY.md`，不要期待 `type` / `novel-type` 字段。
2. **兜底询问**：证据不足或两种子类型都成立（既要连载爽感又要西幻世界观）→ 进入步骤 3 询问用户。

> 子类型判定结果与项目类型一并写入 `.agents/memories/project.md`。

### 步骤 1c · 首次记忆初始化（缺失时补齐）

`.agents/memories/` 不存在、`project.md` 缺失或缺少「项目概览」、`user/` 下没有可用文件时，在判定完项目类型（与小说子类型）后补齐缺失部分，再进入步骤 2：

1. 创建 `.agents/memories/`（已存在则保留）。
2. 写 `project.md`，至少包含：
   - 类型 / 子类型、推断依据、用户确认状态；
   - **项目概览**：一句话定位、目标读者、主要内容范围与关键目录、当前阶段、已知约束与待确认项。
   - 未确认的内容标「待确认」，不得编造。
3. 创建用户记忆 `.agents/memories/user/default.md`（已知用户名时用 `<用户名>.md`），只写本次可观察到的协作偏好；没有可靠信息时保留标题与「待确认」，不要凭空推断性格。
4. 只补齐缺失部分；已有内容只增量更新，不重建、不覆盖。

> 总结性信息集中写进 `project.md` 的「项目概览」；细节仍按类别写入 `outline.md`、`characters.md` 等文件。

### 步骤 2 · 输出类型声明（必做）

在任何实质工作开始之前，**先单独输出一行**类型声明，格式固定：

```text
项目类型：blog（依据：SUMMARY.md 的 description 与按主题分组的文章目录）
项目类型：tech（依据：SUMMARY.md 标题与目录结构推断：含 docs/、api/ 等工程目录）
```

- 类型只能取 `blog`、`novel`、`website`、`tech`、`book` 五个值。
- 类型为 `novel` 时，声明之后**紧接一行**子类型声明：

```text
小说子类型：online（依据：摘要提到连载与日更，正文按境界升级推进）
小说子类型：western-illusion（依据：正文出现魔法体系、种族与公会设定，按子类型判定表推断）
```

- 子类型只能取 `online`、`western-illusion`、`simple` 三个值。
- 声明之后如果依据发生变化（例如用户纠正了类型），必须**重新声明一次**，再继续工作。

### 步骤 3 · 不确定就问，不要猜

出现下列任一情况，**停止猜测**，先向用户提问并等待回答：

- `SUMMARY.md` 不存在，或缺少 `title` / `subtitle` / `description` 等可用线索；
- 两种以上类型同时成立且证据相当（例如「技术博客 + 个人随笔」）；
- 站点是混合形态（既有产品页又有长文），无法判断主次；
- 用户的要求明显不属于已知的五类（例如「做一份活动海报文案」「整理 podcast 字幕」）；
- 类型为 `novel` 但子类型无法判定（例如既要连载爽感又要完整西幻体系，且体裁特征冲突）。

提问格式（一次问清，不要挤牙膏）：

```text
我需要先确认项目类型。SUMMARY.md 的信息不足以唯一判定，候选如下：
A. blog —— 站点以定期更新的观点/评测文章为主，当前 description 提到「随笔」
B. tech —— 站点以工程实现与接口文档为主，当前目录含 docs/ 与 api/
你希望按哪一类工作？（我倾向 A，因为它与 description 的表述最接近）
```

小说子类型的提问同理，例如：

```text
我需要先确认小说子类型。当前文本两种特征都成立，候选如下：
A. online —— 章节短、更新频繁、主角有金手指并按境界升级
B. western-illusion —— 有魔法体系、种族与公会设定，按冒险旅程推进
你希望按哪一类写？（我倾向 B，因为世界观设定占了开篇三章的一半篇幅）
```

- 提问后**必须等待用户回答**，不要同时开始写作。
- 用户回答后，先输出类型声明，再继续。

### 步骤 3b · 创作进度回顾（仅 `novel`）

**所有小说技能共用这一套流程，技能文件里不再重复。** 进入任何小说技能的「输入 / 执行步骤」之前，先完成一次进度回顾，并先交付「创作进度回顾」块：

1. **读记忆**：先读 `.agents/memories/project.md`、`outline.md`，再按需读 `characters.md`、`world.md`、`continuity.md`、`preferences.md`、`style.md`；目录或文件不存在就跳过，不视为错误。
2. **扫数据**：扫描源目录的卷 / 篇 / 章文件（`online` 与 `western-illusion` 按卷 / 章，`simple` 按篇 / 章）；若项目根存在 `.workshop/`，按 §5.5 读取设定卡、地名、关系与候选条目。
3. **统计**：按下面的数据表汇总卷 / 篇 / 章数、字数、最近更新、伏笔回收、人物与设定条目；每项数值注明「来源」，无法从文件得到时标「未记录」，不估算、不编造。
4. **对齐**：记忆与正文冲突时以正文为准；回顾结论写回 `outline.md`（进度、伏笔）及受影响的类别文件。
5. **输出回顾**：先交付「创作进度回顾」块，再继续该技能后续的输入与执行步骤。

```markdown
## 创作进度回顾
- 当前阶段：<开坑 / 连载中 / 修稿 / 完结>（依据：<...>）
- 上次更新：<日期 / 最新一章>（依据：<...>）

| 项 | 数值 | 来源 |
|---|---|---|
| 卷 / 篇数、章数 | <...> | <...> |
| 已完成章节 | <...> | <...> |
| 总字数 / 章均字数 | <...> | <...> |
| 伏笔 | 埋 <X> / 收 <Y> / 未收 <Z> | <...> |
| 人物 / 地点 / 关系 / 候选 | <...> | <...> |
| `.workshop` 设定卡 | <... / 无> | <...> |

- 当前进度：<写到哪一卷 / 哪一篇的哪一章，主线停在哪>
- 待续事项：<接下来 1–3 件，按优先级>
```

### 步骤 4 · 加载技能并执行

1. 读取 `.agents/<type>/` 下与本次任务相关的技能文件（每个 `.md` 是一个独立技能）；类型为 `novel` 时读取 `.agents/novel/<subtype>/`。
2. 按技能文件的「执行步骤」执行，用「输出格式」交付，用「质量检查清单」自检。**小说任务先按步骤 3b 输出「创作进度回顾」，再执行技能正文。**
3. 引用外部结论时附上参考资料链接。
4. 评审 / 评价类技能若项目根存在 `.git/`，先按 §5.6 读取当前改动并结合记忆做综合评价；git 只读，不提交。

> 技能文件是**工作规范**，不是灵感库。执行前必须真正读取对应文件，不要凭印象套模板。

### 步骤 5 · 按需更新记忆

任务结束时，把**下次运行还需要**的信息写回 `.agents/memories/`：

- 类型 / 子类型判定结果 → `project.md`
- 用户新增的偏好、工作方式、创作习惯或明确纠正 → `user/<用户>.md`
- 一般性的协作偏好与禁区 → `preferences.md`
- 新确定的人物、设定、大纲进度、伏笔状态 → 对应类别文件
- 本次的进度、字数与伏笔状态变化 → `outline.md`（进度快照与创作数据）
- 本次发现并修复的连续性问题 → `continuity.md`

一次性内容不写；读写规则与用户画像评估见 §5。

## 1. 类型判定表

| 类型 | 适用站点 | 判定线索（`title` / `subtitle` / `description` / 目录结构） | 技能目录 |
|---|---|---|---|
| `blog` | 博客、专栏、随笔、评测、教程型内容站 | 定期发布文章；有「随笔 / 专栏 / 评测 / 手记 / 笔记」等词；有按时间或主题分组的文章目录 | `.agents/blog/` |
| `novel` | 小说、剧本、诗集等文学创作 | 「长篇 / 连载 / 章节 / 人物 / 情节 / 剧」；目录按卷、章、幕划分；文章篇幅长且有连续情节 | `.agents/novel/<subtype>/` |
| `website` | 产品站、机构站、落地页、FAQ 站 | 「产品 / 服务 / 方案 / 定价 / 关于我们 / 常见问题」；目录是功能页而非文章集 | `.agents/website/` |
| `tech` | 技术博客、工程文档、教程与源码说明站 | 「架构 / 源码 / 部署 / 性能 / 踩坑 / API / 实现」；含代码块、命令、配置文件；目录含 `docs/` `api/` `guide/` | `.agents/tech/` |
| `book` | 读书、书评、书摘、书单、读书笔记站 | 「书单 / 书评 / 读后感 / 笔记 / 摘录 / 共读」；以书为单位组织内容，常见作者 / 译者 / 出版社 / ISBN 等字段 | `.agents/book/` |

**混合站点的处理**：先定「主类型」，再跨目录借用其它类型的技能。例如「技术博客里夹了三篇书评」→ 主类型 `tech`，书评部分调用 `.agents/book/book-review.md`。

**小说类型的子目录**：`novel` 下再分三个子类型目录，判定规则见「步骤 1b」。

| 子类型 | 技能目录 | 核心差异 |
|---|---|---|
| `online` | `.agents/novel/online/` | 连载节奏：黄金三章、爽点密度、章末钩子、金手指与升级体系 |
| `western-illusion` | `.agents/novel/western-illusion/` | 世界观自洽：魔法体系与代价、种族与势力、位阶标尺、冒险旅程 |
| `simple` | `.agents/novel/simple/` | 通用基线：人物驱动、生活细节、克制表达、情感张力 |

> 子类型不同，规范差异很大：**不要跨子类型混用技能文件**，需要时以 `simple` 为基线再叠加对应子类型的专项要求。

| `key-idea-extractor.md` | 需要提炼核心观点、生成读书卡片时 |
| `reading-notes.md` | 需要写结构化读书笔记时 |
| `comparable-books.md` | 需要找同类书、对比多本书时 |
| `book-review.md` | 需要写书评时 |
| `reading-plan.md` | 需要排阅读计划、跟踪进度时 |

## 3. 技能文件的通用结构

每个技能文件都遵循同一结构，便于快速定位：

```text
用途        → 这个技能解决什么问题
何时使用    → 触发条件
输入        → 执行前需要拿到的材料（缺失时向用户索取）
执行步骤    → 编号步骤，可直接照做
输出格式    → 交付物的骨架（模板，不是正文）
质量检查清单 → 交付前逐条自检
参考资料    → 外部依据，引用时给链接
```

> 小说任务的「创作进度回顾」由 §0 步骤 3b 统一规定，技能文件不再单独写这一节。

**执行原则**

- 只使用技能文件里列出的输入；缺输入就问，不要编造事实、数据、引用。
- **小说任务先按步骤 3b 输出「创作进度回顾」**，再进入具体工作；回顾数据必须注明来源，取不到就写「未记录」。
- 事实性内容（数据、引文、书名、版本号、API 行为）不确定时标注「待核实」，不要虚构。
- 交付后必须过一遍「质量检查清单」，并说明未通过项及原因。
- 一次任务可串联多个技能，但要说明串联顺序。

## 4. 目录约定

```text
<项目根>/
├── AGENTS.md              ← 短入口：提示先读 .agents/AGENTS.md
├── .agents/               ← 技能库与记忆（安装到项目根）
│   ├── AGENTS.md          ← 本文件（技能总纲）
│   ├── blog/  book/  tech/  website/
│   ├── novel/             ← 小说按子类型再分目录
│   │   └── online/  western-illusion/  simple/
│   └── memories/          ← 跨会话记忆（AI 运行时创建，按类别分文件，见 §5）
│       ├── project.md     ← 类型 / 项目概览
│       ├── …              ← preferences / style / outline / characters / world / continuity
│       └── user/          ← 用户画像：user/<用户>.md（默认 default.md）
├── .workshop/             ← 可选：创作资产库（设定卡 / 地名 / 关系 / 候选 / 图谱，见 §5.5）
├── <source>/              ← 源目录（src/ 或 posts/）
│   ├── .agents/skills/    ← 同源技能镜像（仅示例内容带；不参与构建）
│   ├── SUMMARY.md         ← 主 SUMMARY.md：站点标题 / 副标题 / 描述 / cover / logo
│   └── …                  ← 文章 / 卷 / 章
├── camus.yaml             ← 站点配置
└── theme/                 ← 主题模板
```

- **技能权威副本**是 `.agents/<type>/**/*.md`；示例内容里的 `posts/.agents/skills/` 是同一套技能的随站分发镜像。
- `AGENTS.md` 与任意 `.agents/` 目录在构建时强制忽略（与 `private` 同级），不会出现在构建产物中。
- `.agents/memories/` 由 AI 在运行中创建与维护，不属于安装包内容，也不参与构建。
- `.workshop/` 为可选的创作资产库，存在时按 §5.5 读取；不存在不视为错误，也不参与构建。
- 项目根 `AGENTS.md` 是短入口；`--copy` 时若已存在则跳过并打印错误（不覆盖用户已有文件），`--force` 才覆盖；`--new` 下若内容不同仍按冲突处理。`.agents/` 内文件冲突时提示并终止复制，请自行合并或用 `--force` 覆盖。

## 5. 记忆（memories）

> 跨会话需要保留的信息，**分门别类写成独立文件**放在项目根的 `.agents/memories/` 下；下次运行先读再干活。

### 5.1 何时写入

- **首次运行**：完成类型（与小说子类型）推断后，立即写入 `project.md`（含「项目概览」），并创建 `user/<用户>.md`（默认 `default.md`），见步骤 1c。
- **用户确认或纠正**：用户明确表态（类型、文风、禁区、命名、篇幅、工作方式）时，更新 `preferences.md` 与 `user/<用户>.md`。
- **产出稳定的长期信息**：人物档案、世界观设定、大纲进度、伏笔状态等需要在多个会话复用的内容。
- **一次性内容不写**：临时草稿、单次问答、未确认的猜想只留在对话里。

### 5.2 文件分类

| 文件 | 放什么 | 不写什么 |
|---|---|---|
| `project.md` | 项目类型、小说子类型、推断依据、用户确认记录、首次初始化的项目概览（定位 / 读者 / 范围 / 阶段 / 约束） | 具体情节 |
| `preferences.md` | 用户偏好：语气、篇幅、更新节奏、禁区与尺度、命名习惯 | 作品设定 |
| `style.md` | 文风约定：人称、时态、句长、术语表、禁用词 | 情节梗概 |
| `characters.md` | 人物档案、关系网、弧线节点、语言特征 | 正文段落 |
| `world.md` | 世界观：魔法体系、种族与势力、地图与地标 | 人物的私密动机（放 `characters.md`） |
| `outline.md` | 结构、分卷 / 章节大纲、当前进度、进度快照与创作数据（章数 / 字数 / 伏笔统计）、伏笔状态 | 已完成章节的正文 |
| `continuity.md` | 事实台账、已发现的一致性问题与处理结果 | 未经核实的主观判断 |

> 分类可按项目需要增删；**一个文件只放一类信息**，文件名用上表的 kebab-case 命名（`user/` 例外，按用户名命名，见 §5.2.1）。

### 5.2.1 用户记忆（`user/`）

`.agents/memories/user/` 按用户分文件：`user/<用户名>.md`；无法确定身份时用 `user/default.md`。**一个用户一个文件，不把不同用户合并。**

用于记录会影响后续协作的稳定信息：

| 维度 | 记什么 | 不记什么 |
|---|---|---|
| 性格与沟通 | 偏好直接 / 委婉、节奏、解释深度、反馈方式 | 心理诊断、人格标签 |
| 工作方法 | 先大纲还是先正文、迭代方式、评审与确认习惯、工具偏好 | 一次性任务安排 |
| 喜好与禁区 | 题材、语气、篇幅、命名、尺度、明确反感 | 未经确认的猜测 |
| 创作习惯 | 人称 / 时态、结构、节奏、母题、审美参照 | 具体作品情节 |
| 协作偏好 | 提问频率、是否要方案对比、决策方式 | 敏感个人信息 |

建议结构（可按需增删）：

```markdown
# 用户画像：<用户>

## 沟通与协作
- <结论>（依据：<...>；日期：<YYYY-MM-DD>；确认状态：用户确认 / 观察推断 / 待确认）

## 工作方法
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）

## 喜好与禁区
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）

## 创作习惯
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）
```

写法：

1. **只在有依据时写**：来自用户明确表达、反复出现的行为或作品特征；单次偶然表现不算。
2. **区分确认状态**：每条标「用户确认 / 观察推断 / 待确认」+ 依据 + 日期；推断不得写成定论。
3. **增量更新**：用户纠正时立即改；不因一次例外推翻长期结论。
4. **不写敏感信息**：与 §5.3 第 5 条一致。
5. **按需读取**：创作、改写、评审、规划、风格与方案类任务先读；机械任务可跳过。

### 5.2.2 用户画像的主动评估

在以下时机主动做一次简短评估，并把**稳定、可复用**的结论增量写入 `user/<用户>.md`：

- 首次运行（初始化）；
- 任务结束，出现新的重复偏好、有效的工作方法或明确禁区；
- 用户纠正 AI 的判断或表达不满；
- 同一信号连续出现 3 次以上（可提高置信度，但仍标注依据）。

评估维度按 §5.2.1 的表；没有新信息就不写，不为「有记忆」而凑内容。评估结论用于调整提问方式、方案详略、写作风格与交付顺序，不用于给用户贴人格标签。

评估不打断主任务：首次初始化或任务结束时做增量更新，必要时用一句话说明；不确定或涉及敏感信息时先问，不擅自写入。

### 5.3 读写规则

1. **先读后写**：每次运行先读 `.agents/memories/` 中已有的文件（项目记忆与按需的用户记忆）；目录不存在就跳过，不视为错误。
2. **增量更新**：只改受影响的条目，不整篇重写；每条记录写清「依据 / 日期 / 确认状态」。
3. **冲突以正文为准**：记忆是工作缓存，不是事实来源；与正文或用户新指令冲突时，以正文 / 新指令为准，并同步修正记忆。
4. **控制体量**：单文件过大（经验值：超过约 200 行）就按主题拆分，避免把记忆写成第二部作品。
5. **不写机密**：密码、令牌、密钥、他人隐私不写入记忆。
6. **不影响构建**：`.agents/` 位于项目根，不在构建扫描范围内；源目录内若出现同名 `.agents/` 也会被构建强制忽略（与 `private` 同级），不会被扫描或发布。
7. **用户画像不越界**：只记录可观察、可复用的协作偏好；不确定就先问，不把推断写成事实，不给用户贴人格标签。

### 5.4 创作进度回顾

小说任务的进度回顾已统一并入 §0 步骤 3b（含数据源、统计口径、输出模板、回写与冲突处理），技能文件与本节都不再重复；执行小说任务时直接按步骤 3b 输出「创作进度回顾」块。

### 5.5 `.workshop` 数据源

项目根存在 `.workshop/` 时，小说技能应把它当作**创作资产库**一并读取；不存在就跳过，不视为错误。

| 文件 | 内容 | 读取方式 / 用途 |
|---|---|---|
| `project.md` | 项目总览、设定、总纲 / 章节清单 | 纯 Markdown；对照总纲与分析范围，注意它可能只是计划 |
| `overview.md` | 总览 | 可为空，空文件跳过 |
| `sheets.md` | 设定卡（人物 / 族群 / 职业 / 籍贯 / 关系 / 备注） | `##` 分卡，`- 字段: 值` 取字段；建人物与关系底账 |
| `places.md` | 地名（族群 / 备注 / 结构） | 同上；建地点底账 |
| `relations.md` | 关系（来源 / 目标 / 关系类型） | 同上；校验关系与图谱连线 |
| `candidates.md` | 名称候选（族群 / 类型 / 性别 / 稀有度 / 字数 / 来源 / 收藏） | 同上；找尚未使用的命名资产 |
| `graph.md` | 节点数 / 连线数 / 快照 / 布局坐标 | Markdown 表格与列表；核对数量与孤儿节点 |
| `preferences.md` | 生成规则与候选筛选条件 | JSON 代码块；只作生成偏好，不作情节事实 |
| `sheets.ini` | 人物 / 候选速查 | INI；与 `sheets.md` 交叉核对，冲突以 `sheets.md` 为准 |

`.workshop/` 是资产库，不是事实来源：与正文冲突时以正文为准，并把差异记入 `continuity.md`；不要静默采信任何一方。

### 5.6 评价类技能与 `.git`

评审 / 评价类技能（`code-review`、`architecture-review`、`*-audit`、`*-score`、`continuity-audit`、`readability-score` 等）在项目根存在 `.git/` 时，不能只看用户贴出的片段，必须结合仓库状态与记忆做一次综合评价。

1. **判断**：只检查项目根是否存在 `.git/`；不存在就跳过本节，按原技能执行。
2. **只读**：`git` 只用于读取，不执行 `add` / `commit` / `reset` / `checkout` / `clean` 等写操作。
3. **读状态**：至少读取 `git status --short`、`git diff --stat`、`git diff`（未暂存）与 `git diff --cached`（已暂存）；需要时读 `git log -1 --oneline` 确认基线。
4. **读记忆**：按任务读 `.agents/memories/` 中相关文件（`project.md`、`preferences.md`、`style.md`、`outline.md`、`continuity.md` 等），以及 `user/<用户>.md` 中的协作偏好与评审习惯。
5. **综合判断**：把「当前改动」与「记忆中的项目目标、偏好、结构、约定」对照，评价范围、一致性、连续性、风险与验证情况。
6. **诚实**：git 命令不可用、仓库无改动或输出为空时如实说明；不得编造 diff、提交记录或文件名。
7. **不改仓库**：评价结论只写进交付物或 `.agents/memories/`，不自动提交。

输出至少包含：改动概览（文件 / 行数）、与记忆的一致性、风险项、验证情况、明确结论。

## 6. 与 Camus 的衔接

- 内容写入 `posts/`（或 `src/`），目录需要标题就放一个 `SUMMARY.md`；新建文章可用 `camus --create <path>`。
- 构建：`camus --build`；只校验配置与目录：`camus --check`（加 `--fix` 自动补 `title` / `create-time` / `SUMMARY.md`）。
- 修改 `SUMMARY.md` 的 front matter 可设置 `title`、`subtitle`、`description`、`cover`、`logo`；项目类型与小说子类型**不写入配置**，由 AI 首次运行时推断并记入 `.agents/memories/project.md`。
- 写作前先看站点已有文章，避免选题重复（可用 `.agents/blog/related-post-finder.md`）。
