# 通用规则（所有技能共用）

> **纪律红线（最高优先级）见 `AGENTS.md` §0**；本节只补细节，冲突时以纪律红线为准。执行任何技能前先读本文件，再按任务读取 `memory.md`、`workshop.md`、`git-review.md`、`novel-map.md`。

## 1. 输入与缺失处理

| 输入 | 从哪里取 | 缺失时 |
|---|---|---|
| 项目记忆 | `.agents/memories/project.md` 等，见 `memory.md` | 标「待补」，不要猜 |
| 用户记忆 | `.agents/memories/user/<用户>.md`（默认 `default.md`） | 跳过，不据此下结论 |
| 正文 | `posts/`（不存在则 `src/`） | 说明「只有大纲」模式 |
| 主 `SUMMARY.md` | 源目录根部 | 只用文件路径与标题分析，并说明 |
| `.workshop/` | 项目根，见 `workshop.md` | 跳过，不编造卡片 |
| 私有目录 | 源目录内任意 `private/`（含 `src/private`、`posts/private`） | **默认不读取**；只有用户明确要求时才读，且不写入公开输出或记忆 |
| 用户本轮要求 | 对话 | 必须先问，不要替用户决定 |

缺失关键输入时，先问一个具体问题并给出可选方向；能靠已有材料推进的，明确标注假设与影响范围。**禁止把推断写成事实。**

## 2. 证据与事实

- 数字、引文、书名、版本号、API 行为、外部事实必须有来源；无法核实标「待核实」。
- 区分「正文事实 / 用户确认 / 观察推断 / 待确认」；推断不得冒充定论。
- 不编造文件名、提交记录、diff、统计值或设定出处。
- 引用外部结论时附链接；链接失效或无法访问时说明。

## 3. 输出纪律

- 先给结论，再给依据与细节；长报告先给摘要表。
- 建议分「必修 / 建议 / 可选」或等价优先级，不制造焦虑式清单。
- 每条问题给可执行改法；不能执行的（需用户决策）单独列出。
- 不把风格偏好当成事实错误；不把「我不喜欢」写成「不正确」。
- 修改类任务说明改动范围与未覆盖部分。
- **写权限**：除非用户明确要求或授权，**不修改源目录 `src/` 或 `posts/` 中的任何内容**（新建、改写、移动、删除、重命名、格式化、批量替换都算）。评审、分析、规划、给建议默认只读；需要落盘时先列出将改的文件并取得确认。`.agents/memories/` 的按需记忆写入不在此限。
- **私有目录**：读取、分析、评审与统计默认跳过源目录内任意 `private/` 目录；只有用户明确要求时才读取，且不得把其中内容写入公开输出、示例、提交信息或 `.agents/memories/`。

## 4. 记忆与用户画像

- 记忆路径、分类、首次初始化、读写与用户画像规则统一见 `memory.md`。
- 记忆是工作缓存，不是事实来源；冲突优先级：正文 > 用户新指令 > `.agents/memories/` > `.workshop/`。
- 只写稳定、可复用的信息；一次性内容不写；敏感信息不写。

## 5. 技能协作

- 本文件与 `memory.md` 是默认必读；`workshop.md`、`git-review.md`、`novel-map.md` 按任务读取。
- 技能文件中的「输入」「质量检查清单」优先列本技能特有项；通用项以本文件与对应公共文件为准，不重复定义冲突规则。
- 技能之间串联时说明顺序与各自产出，不重复同一份通用规则。
