# 记忆与用户画像

> 本文件是 `.agents/memories/` 的唯一细则来源；`AGENTS.md` 的强制工作流负责触发时机，各技能文件只引用本文件，不重复路径与规则。

## 1. 位置与结构

```text
<项目根>/.agents/memories/
├── project.md        # 类型 / 子类型、依据、确认状态、项目概览
├── preferences.md    # 语气、篇幅、更新节奏、禁区与尺度、命名习惯
├── style.md          # 人称 / 时态、句长、术语表、禁用词
├── characters.md     # 人物档案、关系网、弧线节点、语言特征
├── world.md          # 世界观、魔法体系、种族与势力、地图与地标
├── outline.md        # 结构、分卷 / 章节大纲、进度、创作数据、伏笔状态
├── continuity.md     # 事实台账、一致性问题与处理结果
└── user/
    ├── default.md    # 无法确定用户身份时
    └── <用户名>.md   # 一个用户一个文件
```

安装包不创建该目录，`--new` / `--copy` / `--force` 也不复制或覆盖其中的内容；项目根 `.agents/` 不参与构建。

## 2. 首次初始化

`.agents/memories/` 不存在、`project.md` 缺失或缺少「项目概览」、`user/` 下没有可用文件时，在项目类型（与小说子类型）判定后执行以下初始化（触发时机见 `AGENTS.md` 步骤 1c）：

1. 创建目录（已存在则保留）。
2. 写 `project.md`：类型 / 子类型、推断依据、用户确认状态，以及「项目概览」（定位、目标读者、内容范围与关键目录、当前阶段、已知约束、待确认项）。
3. 创建 `user/default.md`（已知用户名时用 `user/<用户名>.md`），只写可观察的协作偏好；没有可靠信息就保留标题与「待确认」。
4. 只补齐缺失部分；已有内容只增量更新，不重建、不覆盖。

## 3. 何时写入

- 首次运行：见上节。
- 用户明确确认或纠正：类型、文风、禁区、命名、篇幅、工作方式。
- 产出稳定的长期信息：人物、世界观、大纲进度、伏笔状态等。
- 一次性内容不写：临时草稿、单次问答、未确认的猜想只留在对话里。

## 4. 文件分类

| 文件 | 放什么 | 不写什么 |
|---|---|---|
| `project.md` | 项目类型、小说子类型、推断依据、用户确认记录、项目概览 | 具体情节 |
| `preferences.md` | 用户偏好：语气、篇幅、更新节奏、禁区与尺度、命名习惯 | 作品设定 |
| `style.md` | 文风约定：人称、时态、句长、术语表、禁用词 | 情节梗概 |
| `characters.md` | 人物档案、关系网、弧线节点、语言特征 | 正文段落 |
| `world.md` | 世界观：魔法体系、种族与势力、地图与地标 | 人物的私密动机 |
| `outline.md` | 结构、分卷 / 章节大纲、当前进度、进度快照与创作数据、伏笔状态 | 已完成章节的正文 |
| `continuity.md` | 事实台账、已发现的一致性问题与处理结果 | 未经核实的主观判断 |
| `user/<用户>.md` | 用户画像：性格与沟通、工作方法、喜好与禁区、创作习惯、协作偏好 | 敏感个人信息、人格诊断、一次性任务安排 |

分类可按项目需要增删；一个文件只放一类信息。除 `user/` 按用户名命名外，文件名用 kebab-case。

## 5. 用户记忆（`user/`）

路径：`.agents/memories/user/<用户>.md`；无法确定身份时用 `default.md`。一个用户一个文件，不合并不同用户。

| 维度 | 记什么 | 不记什么 |
|---|---|---|
| 性格与沟通 | 直接 / 委婉偏好、节奏、解释深度、反馈方式 | 心理诊断、人格标签 |
| 工作方法 | 先大纲还是先正文、迭代方式、评审与确认习惯、工具偏好 | 一次性任务安排 |
| 喜好与禁区 | 题材、语气、篇幅、命名、尺度、明确反感 | 未经确认的猜测 |
| 创作习惯 | 人称 / 时态、结构、节奏、母题、审美参照 | 具体作品情节 |
| 协作偏好 | 提问频率、是否要方案对比、决策方式 | 敏感个人信息 |

建议结构（可按需增删）：

```markdown
# 用户画像：<用户>

## 沟通与协作
- <结论>（依据：<...>；日期：<YYYY-MM-DD>；确认状态：用户确认 / 观察推断 / 待确认）

## 工作方法
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）

## 喜好与禁区
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）

## 创作习惯
- <结论>（依据：<...>；日期：<...>；确认状态：<...>）
```

### 5.1 按需读取

创作、改写、评审、规划、风格调整与方案类任务先读；纯事实查询或机械操作可跳过。读取后用于调整提问方式、方案详略、写作风格与交付顺序，不用于给用户贴人格标签。

### 5.2 主动评估

在以下时机做一次简短评估，把稳定、可复用的结论增量写入 `user/<用户>.md`：

- 首次运行；
- 任务结束，出现新的重复偏好、有效工作方法或明确禁区；
- 用户纠正 AI 的判断或表达不满；
- 同一信号连续出现 3 次以上。

没有新信息就不写，不为「有记忆」而凑内容。评估不打断主任务：首次初始化或任务结束时增量更新，必要时用一句话说明；不确定或涉及敏感信息时先问，不擅自写入。

## 6. 读写规则

1. **先读后写**：每次运行先读 `project.md` 与按需的 `user/<用户>.md`；目录不存在就跳过，不视为错误。
2. **增量更新**：只改受影响的条目，不整篇重写；每条写清「依据 / 日期 / 确认状态」。
3. **冲突以正文为准**：记忆与正文或用户新指令冲突时，以正文 / 新指令为准，并同步修正记忆。
4. **控制体量**：单文件超过约 200 行就按主题拆分。
5. **不写机密**：密码、令牌、密钥、他人隐私不写入记忆。
6. **用户画像不越界**：只记录可观察、可复用的协作偏好；不确定先问，不把推断写成事实。
